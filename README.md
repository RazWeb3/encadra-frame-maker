# Encadra フレームメーカー（encadra-frame-maker）

これは、Encadra（スマホを縦に持ったまま、撮影前に比率とフレームを固定して撮るカメラアプリ）のカスタムフレームを作るための道具「フレームメーカー」を、あなたの個人用AIアシスタント **Muse** に作ってもらうためのリポジトリです。

使い方: このリポジトリのURLを、あなたの Muse に渡して「このリンクを読んで、Encadraのフレームメーカーを作って」と伝えるだけです。Muse が下記の指示書を読み、あなた専用のフレーム作成Space（Webアプリ）を作ります。新しい版が出たら、新しいリリースのURLを渡すだけで、あなたのデータ（デザイン・テンプレート・ギャラリー）を保ったまま更新されます。

以下の本文は、Muse に向けた指示書です。参照コード（`reference/frame-engine.js`）は、フレーム生成の核になる計算の実装です。ライセンスは MIT です。

これは、ユーザーの個人用AIアシスタント（以下「あなた」）に読ませるための指示書です。

ユーザーが「Encadraのフレームメーカーを作って」と言ったら、あなたはこの指示書に従って、そのユーザー専用のフレーム作成Space（Webアプリ）を作成してください。完成したSpaceでは、ユーザーがテーマを伝えるたびに、あなた（Muse）が画像を生成し、その画像をレイヤーとして組み立てて、Encadra用の透過フレームPNGを書き出せるようになります。

この指示書は版を重ねて改善されます。ユーザーが新しい版の指示書をあなたに渡したら、§0の手順で既存のSpaceを更新してください。

ユーザーはプログラミングや画像形式の知識を持つ必要はありません。操作はテーマの入力とボタンのタップだけで完結させてください。

Encadraについて: スマホを縦に持ったまま、撮影前に比率とフレームを固定して撮るカメラアプリ。カスタムフレーム機能は、利用者が用意した透過画像を撮影前にセットし、そのまま焼き込んで保存する。フレーム画像の受け口は全面固定フィットのみ（移動・リサイズ・透明度の調整なし）で、位置は画像の作り込みで決まる。

## 0. 読み方（新規作成と更新）

- まず、そのユーザーのフレームメーカーSpaceが既にあるかを確認すること。Spaceには、この指示書の版（バージョン）を記録する場所を持ち、作成時に現在の版を記録しておくこと
- **既存のSpaceがない場合**: この指示書の内容で新規に作成し、版を記録すること
- **既存のSpaceがあり、記録された版がこの指示書より古い場合**: 作り直さず、既存のSpaceをこの指示書の内容に合わせて**更新**すること。更新では、ユーザーのデータ（保存済みのデザイン、名前付きテンプレート、フレームギャラリー、取り込んだ画像）を必ず保持すること。保存形式を変える必要がある場合は、既存のデータを新しい形式へ変換して引き継ぐこと（データを消して作り直さない）。更新が終わったら、版の記録をこの指示書の版に書き換えること
- **版が同じ場合**: 既に最新である旨をユーザーに伝え、再作成や更新をしないこと
- 新規・更新のどちらでも、書き出し仕様（§3）と検証手順（§5）はこの指示書の版の内容に従うこと

### v0.8での変更点（更新のときに差分として適用すること）

- ダミー写真は、共通素材の取得をやめ、作成時にあなたが生成したダミー画像を同梱する方式に戻した（§2.3）

## 1. あなたの役割

- **言語**: 会話の言語は、ユーザーが使っている言語に合わせること。この指示書が日本語で書かれていることは、会話の言語も、作るSpaceの言語も決めない。作るSpaceのUIの既定言語はユーザーの言語（日本語・英語に限らず、韓国語など、ユーザーが使っている言語そのもの）とし、少なくとも英語への切り替えを持たせること。「Museへの依頼文」もユーザーの言語で組み立てること。ただし書き出し仕様（§3）の寸法・ファイル名の形式と、検証手順（§5）は言語によらずそのまま守ること
- ユーザー専用のフレーム作成Spaceを作ること。中心の概念は**レイヤー（層）の積み重ね**であり、フレームは層を重ねた結果として作られること
- テーマに沿った絵の生成は、あなた（Muse）の仕事であること。Space自体は生成・合成・検証・書き出しの道具であり、生成のたびに違うフレームができることがこの道具の価値であること
- 出力されるフレームPNGの仕様（§3）は厳密に守ること。Spaceの見た目やレイアウトはあなたが作るユーザーに合わせて変えてよいが、書き出し仕様と検証手順は変えてはいけない

## 2. Spaceの構成（必須要素）

画面の構成要素はこの節の記述が正本である。要素の過不足がないようにすること。細部の意匠や色は作るユーザーに合わせて変えてよい。核になる計算（書き出し寸法、キーアウト、アート層の予備フィット、ファイル名の整形、検証）は、参照コード `reference/frame-engine.js` の実装を正とし、Spaceの実装に取り込むこと。

### 2.1 レイヤー

画面の中心はレイヤー一覧（上にある層が手前に描かれる）。各レイヤーは表示／非表示、透明度、順序の入れ替え、削除ができる。レイヤーの種類は次の4つで、**どの種類も複数追加できる**。

画像をレイヤーに入れる方法は、ファイル選択とドラッグ＆ドロップの両方を用意すること。対応形式は PNG／JPEG／WebP とする。

それに加えて、**あなた（Muse）が会話の中で生成した画像を、直接Spaceに入れる経路**を必ず用意すること。ユーザーがテーマをあなたに伝えたら、あなたは画像を生成し、Spaceの保存の仕組みを通じて、そのまま対象のレイヤーに入れるところまで行う。ユーザーがファイルをダウンロードして入れ直す必要はない。これがこの道具の標準の流れであり、ファイル選択とドラッグ＆ドロップは、ユーザーが自分の手持ちの画像を入れるための経路である。

1. **AI生成アート層**: あなたがテーマで生成した絵を入れる層。フィットは次の4モードで、既定は「白地を透過化」
- **白地を透過化（自動）**: 画像全体に白地の透過化（キーアウト）をかける。計算は次の1式で固定する。ピクセルの「白からの距離」を d = 255 − min(R, G, B) とし、係数 k を、d ≤ 16 のとき k = 0、16 < d < 80 のとき k = (d − 16) / 64、d ≥ 80 のとき k = 1 とする。**出力アルファ = 元のアルファ × k**。これ以外の解釈（補間の結果にさらに元のアルファを掛ける等）をしないこと。長方形で切り取らないので、モチーフが境界で真っ二つに切れることがない。中央が白く空いた生成絵にそのまま効く。§5の中央チェックは、この処理を適用した後のアルファで判定すること（中央が純白でない絵は、オフホワイト部分にアルファが残って不合格になる。その場合は生成し直すか、予備のはめ方を使うこと）
- 縁マスク: 絵を縁のゾーンだけに収め、中央を取り除く。帯の幅は各辺20%を既定とし、調整できるようにする。中央に色が残っている絵のための手段。マスクの内側の境界には、キャンバスの小さい方の辺の約3%のフェザー（グラデーション）を必ず付け、切断面を目立たせないこと
- 全面＋中央くり抜き: 絵を全面に敷き、中央内側60%の矩形（§3と同じ矩形）をくり抜いて透過にする
- 帯のみ: 上帯または下帯だけに収める。帯の高さはキャンバスの高さの25%を既定とし、調整できるようにする
- フィットの既定はキャンバスへの全面フィット（引き伸ばし）とし、切り抜き（cover）は既定にしないこと（比率の違う素材を切り抜くと、モチーフが大きく失われるため）
- 既存のデザインのレイヤーのモードを、アプリの都合で勝手に変えないこと。既定は新規レイヤーにだけ適用する
2. **AI生成モチーフ層**: 切り抜き素材を置く層。配置は四隅・上中央・下中央・左右中央のプリセットから選び、サイズ（キャンバスの幅に対する%で指定）と透明度を調整できる。白背景で作られた素材のために「白地を透過化」トグルを持ち、既定はオンとする。キーアウトの計算はアート層と同じ式（出力アルファ = 元のアルファ × k）を使うこと（透過済みの部分を不透明に戻さない）
3. **基本フレーム層**: プログラム描画のテンプレート（二重ライン、太枠＋下帯、下帯のみ、四隅の飾り、縁まわり飾り、ミニマル）、色、太さ、帯の高さ、描画モチーフを持つ層。これは土台であり、主役ではない
- 寸法の単位は、キャンバスの短辺に対する%で統一する。太さの既定は2%（調整の目安は0.5〜8%）、帯の高さの既定は16%（目安は5〜30%）
- 描画モチーフの選択肢は、なし／ドット／星／ハート／ダイヤの5つを用意する
- 「四隅の飾り」は四隅に置くL字型の角飾り、「縁まわり飾り」は描画モチーフを縁に沿って等間隔に並べたものとする
4. **テキスト層**: 文字を文字として合成する層。メインテキスト／サブテキスト、位置、揃え、書体、色、サイズを持つ。生成画像の中に文字を入れさせないための担当（生成文字は崩れるため）
- 位置は9アンカー（四隅・上下左右の中央・中心）のプリセットから選ぶ。サイズの単位はキャンバスの短辺に対する%とする
- 書体は、端末の標準フォントからゴシック／明朝／丸ゴシック／手書き風を選べるようにする
- 読みやすさのための属性として、白フチ（ハロー）と帯背景のオン／オフと、その色をテキスト層に持たせること

### 2.2 生成への導線

- テーマの入力は、デザイン全体に対して1つ置くこと。このテーマは、ファイル名（§3）とフレームギャラリー（§2.3）の記録に使う
- アート層とモチーフ層には「Museへの依頼文」を作る仕組みを置くこと。ユーザーがテーマ（例: 旅行、猫、誕生日）を入れると、その層に合った依頼文が次の雛形で組み立てられ、ユーザーはそれをあなた（Muse）との会話に渡すだけでよい。雛形の {テーマ} {比率} {幅} {高さ} は、入力されたテーマと選択中の比率・寸法に置き換える

  アート層用:

  > テーマ「{テーマ}」で、写真フレームの素材になる絵を1枚生成してください。条件: 画角は {比率}（{幅}×{高さ}px相当）。モチーフや飾りは画像の縁の周りの帯（幅・高さの15%程度の内側）だけに配置し、モチーフは欠けずに全体を描いてください。中央は白一色で完全に空けてください。画像の中に文字は入れないでください。

  モチーフ層用:

  > テーマ「{テーマ}」のモチーフを1つ、白一色の背景の上に大きく生成してください。条件: モチーフは欠けずに全体を描いてください。画像の中に文字は入れないでください。

- アプリ内に、使い方を3ステップで示す案内を置くこと: 1) テーマを決めて依頼文をコピー 2) 自分のMuseに渡して画像を作ってもらう 3) できた画像がレイヤーに入ると仕上がる
- 標準の流れは、ユーザーがあなたとの会話でテーマを伝え、あなたが生成して直接レイヤーまで入れる形であること（§2.1）。依頼文の仕組みは、Spaceの中からこの流れを始められるようにするための入口として置くこと

### 2.3 プレビューと保存

- プレビュー背景の切り替え: チェッカー（透過の確認）／ダミー写真（合成の見え方）／白／黒
  - ダミー写真は、Spaceの作成時にあなたが生成したダミー画像（実在の人物ではない風景など）を1枚、同梱すること。ユーザーの実写写真で代用しないこと
- 保存先は、そのSpaceのストレージとする。デザイン（レイヤー構成全体）は自動保存し、名前付きテンプレートとして保存・読み込み・削除もできること
- **フレームギャラリー**: PNGを書き出すたびに、完成フレームを自動で記録すること。各記録にはチェッカー背景に合成した小さなサムネイル（長辺約480px）、比率、日時、テーマ、ファイル名、レイヤー構成全体のスナップショットを持ち、一覧から「呼び出す」で編集状態を復元、「再ダウンロード」で再書き出し、削除ができること。保存は最新60件までとし、60件を超えたら古い記録から自動で削除すること
  - 保存方式: アップロード／生成した画像は画像IDで一度だけ保存し、デザイン・テンプレート・ギャラリーのスナップショットは画像そのものではなく画像IDへの参照を持つこと（スナップショットごとに画像を複製しない。保存容量を圧迫しないため）

## 3. 書き出し仕様（厳守）

- 形式: PNG（アルファ付き）
- 比率とピクセル寸法（長辺1920px統一）:

| 比率 | 寸法 |
|---|---|
| 1:1 | 1920×1920 |
| 4:5 | 1536×1920 |
| 3:2 | 1920×1280 |
| 16:9 | 1920×1080 |
| 9:16 | 1080×1920 |

- 中央の完全透過: キャンバス中央の内側60%（幅・高さとも中央の60%の矩形）は、アルファ値0でなければならない。ただしモチーフ層は例外とし、§5の扱いに従う
- ファイル名: `encadra-frame_{比率の:を-に置換}_{テーマ}.png`（例: `encadra-frame_4-5_travel.png`）
  - テーマ部分の整形ルール（実装ごとに結果が分かれないよう固定する）: テーマ文字列を小文字化し、英字（a-z）と数字（0-9）はそのまま残す。それ以外の文字（空白・記号・日本語など）は、連続するものをまとめてハイフン1つに置き換える。先頭と末尾のハイフンは取り除く。結果が空になった場合（テーマ未入力、または英数字を含まないテーマ）は `myframe` を使う
- 5比率まとめて書き出し: 同じレイヤー構成を各比率に組み直して、5つのPNGをZIPにまとめて書き出せること。ギャラリーには5件それぞれを記録すること
  - 組み直しの規則: 太さ・帯の高さ・テキストサイズ・モチーフサイズは、各比率のキャンバスの短辺に対する%で保つこと（比率が変わっても相対的な大きさが変わらないようにする）。モチーフの配置プリセットは各比率のキャンバスに対して同じ相対位置に置く。アート層の絵は各比率のキャンバスへ全面フィットし直す
- Encadra側の取り込み上限は長辺4,096pxである。本仕様はその範囲内にある
- この寸法表は、参照コード `reference/frame-engine.js` の `SIZES` と同一である

## 4. 生成ルール（あなたが画像を生成するとき）


- **目標比率を生成の時点で指定すること**。素材の比率がフレームの比率と違うと、フィット時にモチーフが切り落ちる
- アート層用: モチーフや飾りは画像の縁の周りにだけ配置し、中央は白一色で空ける（この「白い中央」が、白地を透過化する既定モードの前提になる）
- **モチーフは欠けずに全体が入るように描くこと**。画像の端でモチーフを切らない。画像の端からは余白を取り、飾りは縁の帯（目安として幅・高さの15%程度）の内側に収める
- モチーフ層用: モチーフは単体で、白一色の背景の上に大きく作る（後から切り抜く前提）。透過PNGで直接作れる場合はそれでもよい
- **生成画像の中に文字を入れないこと**。タイトルや日付などの文字は、必ずテキスト層で合成する
- 白背景で生成された画像は、そのままではフレームにならない。白地を透過化（キーアウト）してからレイヤーに入れること。Space側にもこの透過化の処理を持ち、アート層の既定モードにすること

## 5. 検証手順（書き出し前に必ず実行し、結果を表示すること）

1. 実寸チェック: 書き出すPNGのピクセル寸法が §3 の表と一致すること
2. 中央の完全透過チェック: 中央内側60%の矩形内の全ピクセルがアルファ0であること。判定は、モチーフ層を除いた全レイヤーを合成した画像に対して行う
   - モチーフ層は例外として合成から外す。ただし、表示中のモチーフ層が中央の矩形にかかっているかどうかは別に調べ、かかっている場合は不合格にせず、「モチーフが中央にかかっている」旨の警告表示にとどめ、意図した配置かどうかをユーザーが目で確認できるようにすること
3. 描画チェック: 不透明なピクセルが存在すること（空のフレームを書き出さない）
4. 合成チェック: ダミー写真の上に合成したプレビューで、中央の被写体が隠れないこと、テキストが背景やモチーフと重なって読みにくくなっていないことを、ユーザーが目で確認できるようにすること。この項目は目視確認用であり、書き出しを止める合否には含めない

検証に失敗した場合は、そのまま書き出さず、どの項目がなぜ失敗したかを表示すること（モチーフ層の警告は除く）。

## 6. 納品時に伝えること（短く）

新規作成のときも、更新のときも、最後に伝えること。

1. 作ったSpaceで何ができるか（テーマを伝えるたびに新しいフレームが作れること、過去のフレームはギャラリーからいつでも呼び出せること）。更新のときは、何が変わったかを §0 の変更点に沿って短く伝えること
2. 書き出したフレームPNGは、Encadraのカスタムフレームに登録して使うこと（カスタムフレーム機能を持つバージョンが必要）。登録した画像はアプリ内にコピーされるので、元のファイルを消してもフレームは残ること
3. 比率ごとにフレームは別に作るのが基本であること（Encadra側に複数比率向けの自動調整はない）
4. この指示書が新しい版になったら、もう一度あなたに読ませるだけで、作ったSpaceがデータ（デザイン・テンプレート・ギャラリー）を保ったまま更新されること

## 7. してはいけないこと

- 書き出し仕様（§3）と検証手順（§5）を、見た目の都合で変えること
- 生成画像の中に文字を描かせること
- アプリ（Encadra本体）の実装や、透かしロゴの自由配置をフレーム側に持ち込むこと。この道具の担当はフレーム画像の作成だけである
- 更新のときに、ユーザーのデータ（デザイン・テンプレート・ギャラリー・画像）を消して作り直すこと
- 生成した画像の投入を、ユーザーの手作業（ダウンロードとアップロード）だけに頼ること。直接入れる経路を必ず用意すること（§2.1）
- ユーザーの実写写真をダミー写真の代わりに使うこと。合成確認には生成したダミー画像を使うこと
