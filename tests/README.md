# tests/ — フレームメーカー同梱テスト

フレームメーカーのテストは、指示書（`../README.md`）と一緒にこのリポジトリで版管理します。どの利用者の Muse が Space を作っても、同じ物差しで受け入れ確認できるようにするためです。作った側の自己申告ではなく、テストの実測で合否を判断します。

## 構成（2層に分けて管理する）

| 場所 | 内容 | 実行場所 |
| --- | --- | --- |
| `unit/frame-engine.test.js` | frame-engine の純粋計算の単体テスト（寸法表・比率判定・キーアウト・ファイル名・検証計算） | どこでも可。`node --test tests/unit/frame-engine.test.js` |
| `acceptance.md` | Space 実機でしか測れない項目の手順書（生成比率テスト、書き出しと保存の読み戻し、テイスト選択） | 作った Space そのもの |

実機テストが環境要因で止まったときに、計算そのものの合否まで不明にならないよう、この2層は分けて管理します。

## 実行タイミングと不合格時の扱い

規則の正本は指示書 §6「同梱テストの実行」です。要点だけ再掲します。

- 新規作成の直後と、バージョンアップの適用後に、全テストを実行する
- 不合格のときは不合格項目だけを直して再実行する。再試行は最大3回まで、同じテストが同じ数値で2回落ちたら再試行をやめて報告へ切り替える
- バージョンアップ時はデータを消して作り直さない
- 不合格の報告は、テスト名／期待値／実測値／再試行回数／修正提案 の5項目で統一する
