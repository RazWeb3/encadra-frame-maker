# Encadra フレームメーカー 実機受け入れテスト手順

作った Space そのものに対して実行する受け入れテストの手順書です。指示書（README.md）§6 の規則（実行タイミング・再試行の上限・報告形式）とセットで使ってください。単体テスト（`tests/unit/`）とは分けて管理します。実機テストが環境要因で止まっても、単体テストの合否は別に確定できます。

## 共通の約束

- 実行タイミング: 新規作成の直後と、バージョンアップの適用後（見守りの流れ: 新版の通知 → ユーザーの承認 → 更新 → テスト → 結果報告）
- テストで使うテーマは任意（例: 旅行）。ユーザーの既存データ（デザイン・テンプレート・ギャラリー・画像）は消さないこと。テストの書き出しがギャラリーに記録されるのは正常な動作として扱う
- 不合格のときは、不合格項目だけを直して再実行する。再試行は最大3回まで。同じテストが同じ数値で2回落ちたら、再試行をやめて報告へ切り替える
- バージョンアップ時は、データを消して作り直さない（作り直しが許されるのは新規作成のときだけ）

## テスト1: 生成比率テスト（v0.19で追加。今回の回帰テスト）

狙い: アプリ内生成が、依頼した比率どおりの素材を出すことを実測で確かめる。書き出し寸法の確認では検出できない（書き出しは常に仕様どおりの寸法になるため）。

手順:
1. 比率を 3:2 に設定し、アプリ内生成を実行する。生成された素材（レイヤーにはめる前の画像）の実寸（幅×高さ）を記録する
2. 同じ手順を 16:9 / 4:5 / 9:16 でも実行する（1:1 は任意）
3. 各素材について、実寸の縦横比が依頼比率と一致するか判定する。判定はピクセル寸法そのものではなく比率の一致で見る（許容誤差は比率の相対1%。frame-engine の `aspectRatioMatches` と同じ基準）

合格条件: 4比率すべてで比率が一致すること。同方向のペア（3:2 と 16:9、4:5 と 9:16）を必ず含めること。異なる方向同士の比較だけでは、orientation（縦横の向き）への潰し込みを検出できない。

不合格の例: 3:2 で生成 → 素材は 16:9（生成側へ orientation の区分だけが渡り、寸法で指定されていない疑い。指示書 §5 の寸法保証を確認すること）

## テスト2: 書き出しと保存の読み戻し（従来の受け入れ確認）

手順:
1. 任意のテーマと比率で、書き出しを1回実行する
2. 書き出したPNGの実寸が §4 の表と一致すること、検証表示の内容（モチーフの中央警告の有無を含む）を確認する
3. 保存データを読み戻し、その書き出しがフレームギャラリーに記録されていること、記録された版が現在の指示書の版であることを確認する
4. 白地フレームのはめ方（「そのまま」「窓だけ抜く」）を使ったデザインがある場合は、そのデザインでも書き出しを1回実行し、項目2が対象外・項目5で判定されて書き出せること、あわせて窓が不透明な白地フレームでは項目5が不合格と表示され、警告モーダルの確認を経て書き出せること（警告なしには書き出せないこと）を確認する
5. 検証が不合格になるデザイン（例: 中央に薄いピクセルが残るアート）で書き出しを押し、警告モーダルが出ること、「このままダウンロード」でダウンロードとギャラリー記録が行われること、「やめる」で書き出されないことを確認する

合格条件: 読み戻しで記録と版が確認できること。確認できない場合は未完成として報告し、納品したことにしない。

## テスト3: テイスト選択（v0.19で追加）

手順:
1. アート層の編集で、テイストのサムネイルが12種類表示され、題材・構図が揃っていることを確認する
2. テイストを1つ切り替え（例: レトロ）、依頼文を表示して、テイスト名と画風の指定文、および余白を作らない条件（端まで描画）と比率の指定が入っていることを確認する
3. 再読み込み後も、切り替えたテイストがそのアート層に保持されていることを確認する
4. アプリ内生成が使える環境では、テイストを切り替えて生成し、画風が変わることと、生成比率テスト（テスト1）の判定に乗ることを確認する

## 報告形式

合格のとき: 実行したテスト名と、主な実測値（生成比率テストの各比率の実寸など）を短く報告する。

不合格のとき（この5項目で統一する）:
- テスト名：
- 期待値：
- 実測値：（例）3:2 で生成 → 素材は 16:9
- 再試行回数：
- 修正提案：
